# FoGGuard：真实数据识别评估 v2

这一版补齐第四位同学的诊断和失败案例：不仅看识别窗口，还检查冻结表现、动作场景、真实事件，以及没有有效预测的数据。

## 直接验收

解压后双击 `results/真实数据冻结识别验收.html`，Windows 就能看，不需要 Ubuntu、Python 或联网。页面数据已内嵌。

1. 看“哪些冻结表现容易漏掉”，核对拖步、颤动和运动不能三组的召回率。分组依据真值，不是模型在预测亚型。
2. 看“真实冻结事件有没有被覆盖”，注意事件有重叠不等于整个事件都被正确识别。
3. 在最长漏检事件表中点击“查看事件 1”，应跳到 P12/S1/T7，显示真实曲线和冻结标注，并明确提示无有效预测；概率区域留空。
4. 点击有判定但仍完全漏检的案例，再拖动窗口滑块，检查概率与阈值。
5. 切换全部 106 段记录，带“无预测”的 11 段也能看。缺测处留空，不补零；无预测时滑块和逐窗按钮禁用。
6. CSV 可用 Excel 打开；`核验与指标.json` 包含数据哈希、分折、覆盖定义所需参数对应的统计与分组结果；`验证记录.json` 和 `压缩包复核.json` 记录检查情况。

## 这一版发现了什么

**原始数据有 106 段记录，而原来的 OOF 文件只有 95 段有有效预测。** v1 的窗口分析针对这 95 段记录；v2 把另外 11 段也纳入事件和时间覆盖评估、界面展示，避免只看有效输入而漏掉系统覆盖缺口。

11 段均存在模型所需输入通道整段缺失：

- P9/T7：左踝 6 通道与部分背部加速度缺失。
- P12/T7：背部陀螺仪 3 通道缺失。
- P17/T3、T4、T6、T7：左踝和背部所需 12 通道全部缺失。
- P21/T3、T4、T6、T7，P22/T4：背部 6 通道缺失。

详细记录在 `无预测记录问题清单.csv`，其中 `all_missing_input_channels` 列出整段缺失通道。`记录时间覆盖.csv` 也给出原始样本数、不完整输入样本数和有效预测窗口数。原程序不对长时间缺失伪造信号，所以没有生成这些记录的窗口；本次保留该规则。

## 窗口结果：原模型未变

22 位参与者，9,636 个有效窗口，使用既有的 5 折参与者隔离交叉验证预测。

| 指标 | 结果 |
|---|---:|
| TP / TN / FP / FN | 1247 / 6760 / 979 / 650 |
| 冻结精确率 | 56.02% |
| 冻结召回率 | 65.74% |
| 冻结类别 F1 | 0.605 |
| 两类宏平均 F1 | 0.749 |
| 准确率 | 83.09% |
| 始终猜非冻结的准确率 | 80.31% |

2 秒输入窗口含 120 点，首尾时间跨度 119/60 秒；步长 0.5 秒。原始冻结标注占窗口样本 ≥ 50% 时取冻结真值。全部 9,636 个窗口的身份、起止时间、真值和冻结占比重新对照原始 60 Hz 数据，全部一致。训练/测试参与者和每折阈值也已核对。

按参与者整体重采样 2,000 次、固定种子 5412，百分位 95% 区间：召回率 54.1%–80.2%，精确率 32.6%–69.0%。这里重采样整个人的所有窗口，避免把重叠窗口当成独立样本；这些区间只描述当前参与者样本的重采样波动，不包含重新训练的不确定性，也不替代新参与者测试。

## 冻结表现分组

| 数据集真值表现 | 冻结窗口 | 涉及参与者 | 命中 / 漏报 | 召回率 |
|---|---:|---:|---:|---:|
| 拖步 Shuffling | 96 | 7 | 48 / 48 | 50.0% |
| 颤动 Trembling | 397 | 12 | 291 / 106 | 73.3% |
| 运动不能 Akinesia | 1403 | 7 | 908 / 495 | 64.7% |
| 混合表现 | 1 | 1 | 0 / 1 | 0.0% |

仅在窗口真值为冻结时分组；在该窗口的冻结样本中，某个 `fog_severity` 值严格超过 50% 才归入它，其他情况为混合。**只统计各真值组的二分类召回率，不制造“亚型分类精确率/F1”。** 不同组涉及的参与者不同，窗口也有重叠，不能据此断言某种冻结表现本质上更难识别。

官方标签为 Shuffling、Trembling、Akinesia，没有直接叫“动态冻结”的标签。如果“动态冻结”只是指行走中的 FoG，已有二分类识别与动作场景评估；若它指特定亚型，需团队先约定映射和验收标准，本次不自行给这些术语作医学定义。

## 真实事件与时间覆盖

本版的事件是真实逐点 FoG 标注连续段，不是 v1 的“连续错误窗口”，也不是下游脚印提示触发事件，因此数量不可直接混用。

| 项目 | 结果 |
|---|---:|
| 真实事件 | 101 |
| 与模型冻结判定有正时长重叠 | 76（75.25%） |
| 完全没有冻结判定覆盖 | 25 |
| 其中完全没有模型判定支持 | 18 |
| 其中有判定支持但没有冻结报警 | 7 |
| 冻结时间覆盖率 | 56.03% |
| 报警时间精确率 | 54.22% |
| 误报时长 | 507.07 秒 |
| 未被报警覆盖的冻结时长 | 471.45 秒 |
| 有任意模型判定的记录时间比例 | 87.46% |

18 个无模型判定支持事件中，17 个在整段无有效预测的记录里，1 个在末个判定保持期之后。不能把它们都当成分类器已作出非冻结判断；但是从完整链路角度，它们确实没有得到冻结判定覆盖，所以仍保留在 101 个事件的分母中。

定义固定为：

- 真值事件是同一参与者/会话/任务中原始 `fog=1` 样本的连续区间，末样本延长 1/60 秒；不合并中间的非冻结段或记录间隔。
- 模型判定从 `window_end_s` 才可用，最多保持一个 0.5 秒步长，并被下一判定、记录结尾及真实样本观测区间截断。缺少有效窗口时不延长旧结果。
- 本版“报警”指上述二分类冻结判定保持区间，不是声光设备报警，也没有把下游提示控制器、通信和硬件延迟算进去。
- 任意超过 1 微秒的重叠计作事件有覆盖。一个持续报警可覆盖多个真实事件，因此这是**任意重叠覆盖率，不是一对一匹配的事件 F1**。时间精确率同时惩罚真实事件外的报警时间，时间召回率惩罚漏报及无判定支持时间。
- 有覆盖的 76 个事件中，11 个在事件起点前报警已经存在。另 65 个出现新报警的事件，其首次报警重叠相对真值起点的条件中位延迟为 1.18 秒。完全漏检事件不进入此中位数；该数字不能单独代表总体检测延迟，也不是在线硬件实测。

逐事件证据在 `真实冻结事件覆盖.csv`，含真实起止时间、冻结时长、模型支持时长、报警覆盖时长、是否提前已有报警，以及输入不完整样本数；`报警片段.csv` 为对应报警连续片段。

## 场景问题与给队友的建议

`动作分组.csv` 按原始动作标注的唯一多数（≥ 50%）分组，无唯一多数记混合动作。它不是模型转向预测。站立场景有 381 个误报窗口；行走中的冻结召回率为 55.0%；360° 转身任务的召回率为 58.0%（任务与动作是不同字段，结果分别在 `任务分组.csv` 和 `动作分组.csv`）。

建议反馈给第一位：先处理或明确缺失输入的覆盖边界，再研究静止场景误报、转身时漏报和参与者差异。如果设计少传感器备用模型，需用同样的参与者隔离方式重新训练和评估，不能拿当前测试标签调好规则再宣称效果提升。反馈给第二位：数据可用性与非冻结状态应在整合流程里区分；没有输入不能显示成“确定正常”。第三位可使用原来的提示策略评估结果，不应把本版识别覆盖率等同于提示有效率。第五位可以直接使用这里的 CSV、交互页与说明制作展示。

## 当前 GitHub 交付与复现

[总入口](../../AUTOMATION2_START_HERE.md)提供源码运行命令与版本附件链接。当前通过独立 fork/分支和 PR 交付评审，原仓库、v3 集成副本与 v1 交付均保留，不自动合并或关闭任务。

源码在仓库的 `recognition/`，单独检查从仓库根目录运行 `python -X utf8 -m pytest tests recognition -q`。完整检查使用 `python -X utf8 scripts/run_automation2_delivery_checks.py`；不提供真实数据参数时，该项明确为 NOT_RUN。

原始 119 MB 数据和 62 MB 模型不提交到源码库。识别版本附件包含保存的 OOF 输入、训练报告与自包含验收页，不需要重新训练就能查看。复核真实原始标签时需准备同版数据：

```bash
python -m pip install -r requirements.txt
python -m pip install -e .
python scripts/download_fogstar.py
python -X utf8 recognition/evaluate.py --raw data/raw/fogstar/sensor_data.csv --predictions path/to/inputs/fogstar_oof_predictions.csv --training-report path/to/inputs/fogstar_training.json --output reports/recognition-new-run
```

输出目录由底层脚本创建；请使用新目录保留历史结果。若重新训练，则用原 `scripts/train_fogstar_baseline.py`，不能拿全量部署模型对训练数据的预测替代 OOF。本报告复用了保存的 OOF 并核验标签，未再次训练，也不证明历史训练过程没有所有潜在泄漏。

## 数据归属与单位

FoG-STAR v3.0，22 位帕金森病参与者，四处 IMU、60 Hz，视频专家标注。官方记录说明许可为 CC BY 4.0：https://zenodo.org/records/17838806 。页面包含加速度模长、冻结标签及表现/活动注释的派生显示；原始 README 附于 `inputs/README_FoGSTAR.txt`。本项目改编为二分类窗口与离线覆盖统计，未修改原始文件。

引用：Borzì, L. et al., *FoG-STAR: Freezing of Gait Severity, Tasks, Activities, and Ratings* [Data set], Zenodo, DOI: 10.5281/zenodo.17838806。完整作者及相关论文见官方记录。

原 README 将 timestamp 标为 ms，而实际间隔约 1/60，原程序以秒处理。本次检查采样间隔后沿用秒并记录这一不一致。原始缺测处在图中留空，统计窗口仍用原构造器的规则：最多插值 0.1 秒内部缺口，长缺口切开，不跨记录拼接。本结果用于课程算法评估，不构成临床疗效证明；团队尚未给定模型效果通过阈值。
