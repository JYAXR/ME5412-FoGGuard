# FoG 基线阈值标定记录

## 目的与范围

本记录只固定课程合成演示中 `FreezeIndexDetector` 的工程默认阈值。数据均为仓库脚本生成的确定性合成 IMU 场景，不包含参与者数据，也不能证明临床性能或给真实患者选择阈值。公开真实数据结果另见 [Daphnet 验证记录](DAPHNET_VALIDATION.md)。

## 预先声明的规则

- 开发场景：`normal_gait`、`straight_fog`。
- 留出检查场景：`turning_fog`。
- 候选阈值：0.00 至 1.00，步长 0.01。
- 窗口标签：窗口内至少 50% 采样点为 FoG 时记为阳性。
- 选择顺序：开发场景误报数必须为 0；随后依次最大化 F1、召回率和阈值。

该规则中的最后一项会在预测完全相同时选择更高、更保守的阈值。运行命令：

```bash
python scripts/calibrate_fog_threshold.py
```

## 结果

合成演示选择阈值为 **0.21**。

| 数据 | 窗口数 | TP | TN | FP | FN | Precision | Recall | F1 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 开发场景合并 | 114 | 11 | 103 | 0 | 0 | 1.00 | 1.00 | 1.00 |
| 留出转向 FoG | 57 | 11 | 46 | 0 | 0 | 1.00 | 1.00 | 1.00 |

脚本同时把完整 JSON 结果写入被 Git 忽略的 `reports/fog_threshold_calibration.json`，方便本地复核。

## 局限性

开发场景与留出场景来自同一个合成信号生成器，且 FoG 的垂直加速度模式相同，因此留出结果并不等同于独立参与者或真实传感器验证。

Daphnet 的参与者留一实验已经表明真实数据上的最优阈值随留出参与者而变化，各训练折阈值中位数为 0.73；即使如此，合并 precision 仅 0.185、F1 仅 0.287，误报仍过高。因此：

- `0.21` 只用于确定性合成演示；
- `0.73` 只是本次 LOSO 训练折阈值的描述统计，不是新的生产默认值；
- 在改进特征、事件合并和独立验证前，不声明存在一个可安全驱动真实提示的固定阈值。
