# 项目说明

## 项目目标

FoGGuard 是一个基于可穿戴 IMU 的步态辅助研究原型，完成冻结与当前方向感知，并研究如何根据提示后的运动反馈控制脚印和声音提示。最终画面读取保存的算法结果，形成可复现的课程汇报与过程演示。

目标流程为：正常时监测 → 持续冻结且方向有效时给出迈步提示 → 在有效反馈中观察响应 → 持续有效无响应时进入原地交替踱步 → 有可靠交替动作依据后重新尝试前进 → 满足退出条件后停止提示。

## 系统设定

| 项目 | 设定与边界 |
|---|---|
| 真实数据 | FoG-STAR，60 Hz IMU；冻结和活动标签用于训练或离线评价 |
| 冻结任务 | 完整 120 点窗口的冻结/非冻结检测，每 30 点更新，不是冻结前预警 |
| 方向任务 | 当前直走/左转/右转/未知；正式融合不接入提前预测 |
| 感知输出 | `perception_runtime.csv`，记录身份、决策时间、各来源范围与质量、事件和方向 |
| 反馈任务 | B1 待实现：有效动作代理、有效无动作或未知，附来源/可靠性/可用时间 |
| 提示与备用策略 | 有模拟控制基础；真实反馈驱动的前进、踱步、返回和退出由 B1 接入验证 |
| 展示 | A 组图表已交付；最终 PPT、可视化和视频由工业设计制作 |

冻结与转向可以同时发生。静止不直接等于冻结，低冻结分数不直接等于迈步成功；原地动作不等于向前位移。

## 后续工作

B1 从现有感知输出和原始 IMU 开始生成运动反馈，再接入有效无响应时钟和提示切换。B2 同步检查感知接口，接收 B1 后完成组合运行、同输入策略对照、异常验收及最终数据包。工业设计现在可使用统一素材组织 PPT 与视觉风格，随后接入 B2 的保存命令完成最终演示。

各模块都需提供可追溯的过程证据：A 组已有模型与时间线；B1 后续提供真实信号/反馈及切换依据；B2 后续提供策略对比、生命周期审计和失败例。详见 [分工与依赖](ROLES_AND_ROADMAP.md)、[任务书](tasks/B1.md) 和 [项目状态](PROJECT_STATUS.json)。

## 能力边界与评价口径

- 固定 TEST FoG F1 为 0.485 / 0.554 / 0.557，误报漏检仍明显；这是已报告的模型能力，不作为未交付任务。
- 原始方向在 676 个有效明确目标窗口上准确率 81.07%；融合后为 51.78%、覆盖率 54.73%。阶段、分母和拒识分别报告。
- 提前转向预测未达到可用水平，不能把当前动作分类写成可靠的提前意图识别。
- TEST 已用于固定评价。新模型/阈值迭代需另行安排开发与独立评价，本轮维护不重新选择测试最优方案。
- IMU 运动代理不直接测量向前位移；缺独立真值时不报告真实迈步成功率。缺失输入保持未知。
- 工程模拟响应验证控制行为，不作为患者恢复效果。实时计算延迟与临床效果未测量。
- 硬件投影、实测足部定位及人体临床闭环不在本期交付范围。
