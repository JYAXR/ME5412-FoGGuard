# B2：评估与系统联调

## 目标和边界

把 A1、A2、B1 的正式输出接起来，独立检查数据、时序和控制行为，整理足够汇报的比较结果，并交付最终展示读取的数据包。B2 不重训 A1，也不承担最终 3D 画面制作。

## 可用基础

`evaluation/`、`recognition/`、`run_complete_demo.py`、`run_engineering_comparison.py` 和 `verify_engineering_comparison.py` 已提供窗口/事件评价、工程场景、策略比较和命令生命周期审计。

构造候选与模拟响应可先用于接线检查。真实系统结果必须替换为 A1/A2/B1 对应输出，不能把演示输入当成模型成绩。

## 实施顺序

1. 运行 [快速开始](../QUICKSTART.md) 的工程演示与项目检查，建立本地可复现环境。
2. 根据 [接口约定](../INTERFACE_CONTRACT.md) 检查身份键、单位、可用时刻、来源和未知值，分别接入 A1、A2、B1。
3. 对同一记录验证感知融合、反馈观察和提示生命周期。重点检查未来信息、跨记录状态、过期方向、未知反馈和结束撤销。
4. 固定输入及配置，比较固定提示、响应驱动提示和原地踱步分支；间距和渐弱需要时分别做单因素对照。
5. 报告检测、方向、反馈和控制四类结果，保存失败案例及未评价原因。
6. 导出统一结果包和清单，给工业设计使用；与其核对时间线和字幕，确保画面能追溯到保存输出。

## 评价表

| 层 | 必需指标或证据 |
|---|---|
| A1 冻结 | P/R/F1、混淆计数、冻结时间覆盖、误报时间、缺测支持 |
| A2 方向 | 逐类指标、macro-F1、拒识覆盖、逐人结果，提前任务单列 |
| B1 反馈 | 有真值时的分类/事件指标，无真值时的代理说明、有效观察比例和实例 |
| 控制策略 | 首次提示延迟、误提示、切换次数/原因、提示时长、超时及退出 |
| 工程约束 | 未知/过期时的撤销、无跨记录状态、目标范围、命令最终关闭 |

原始事件有报警重叠、完整冻结时长覆盖和提示触发是不同指标，分别统计。工程场景的模拟恢复时间不能作为患者恢复时间。

## 必交付

- 一条组合运行入口，记录原始输入、模型、配置和输出哈希。
- `perception_runtime.csv / feedback_runtime.csv / commands.csv` 及独立真值表。
- `metrics.json`、简短结果说明、失败案例清单和数据来源清单。
- PPT 可用的对比表、指标图和一条真实感知时间线、一条模拟策略时间线。
- 交给工业设计的展示包，包含场景说明、字幕术语和不能用于效果结论的内容。

## 完成条件

新环境能复现保存结果；固定和自适应策略使用相同输入；所有必需场景通过或明确列为未通过；缺失真值不记成零错误。最终报告清楚区分各模块评价和四模块联合验收。
