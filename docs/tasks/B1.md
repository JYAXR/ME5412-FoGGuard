# B1：运动反馈与提示控制

## 目标和边界

真实 A1+A2 感知输出已提供 [运行入口与字段说明](../a2/fusion/README.md)。使用融合表决策时间，保留每个来源的输入范围及有效性；计时/保持行不能增加新的传感器观测，也不能作为未迈步证据。

实现“提示后有无动作响应”的证据生成，并据此控制前进提示、原地踱步和退出。B1 负责算法与过程证据；工业设计负责最终人物、场景和视频。

## 输入与代码基础

输入为 A2 感知事件、原始同步 IMU、提示命令记录，以及明确标注的响应来源。A1 冻结分数不能替代运动响应观测。

`cueing/guidance.py`、`cueing/march.py`、`cueing/contracts.py` 和 `data/responses.py` 提供脚印/声音、响应、原地交替、渐弱与时长限制。现有响应文件用于模拟控制，真实 IMU 反馈仍需实现和适配。

## 先完成运动反馈

1. 选择左右踝运动能量、周期或峰值等可解释信号，明确观察窗、预处理、阈值和有效性规则。
2. 输出动作证据、有效观察中的无动作证据或未知，并给出来源、可用时刻和判据。缺测、信号不可靠和观察不足均为未知。
3. 区分运动、原地交替和向前位移。没有独立位置/步真值时，IMU 输出只能作为运动代理，不声称真实迈步成功率。
4. 真值存在时按参与者隔离评价；真值缺少时提供真实信号实例、代理行为与人工核查范围，分类准确率标为不可评价。

## 再完成策略接入

- 冻结持续确认且方向有效时，给出对应方向的脚印和节拍。
- 从提示实际生效时开始观察。仅累计有效反馈支持的无响应时长；未知不得推进“没迈步”时钟。
- 达到无响应条件进入原地交替踱步；满足可靠交替动作条件后重新尝试前进提示。
- 原地动作不计入向前恢复。向前恢复、感知回落和渐弱/退出各自写明条件。
- 缺少反馈时关闭依赖反馈的自适应分支，保持明确降级；必要感知输入过期时撤销提示。
- 通过独立适配器接入代理反馈，保留真实来源；不要给代理填写虚构的足部位移。

## 配置和检查重点

现有配置包含 3 秒响应超时、3 秒备用阶段和 4 次交替要求。B1 要核对节拍、步数和备用时长的可满足性，给出一致的最终参数，并通过慢节奏、无响应、错误脚别和中断案例。工程参数要写入配置，不作为患者处方。

## 必交付

| 交付 | 内容 |
|---|---|
| 反馈估计器 | 预处理、判据、有效性、来源和可用时刻 |
| 反馈适配器 | IMU 代理与模拟响应分开，正确映射至控制输入 |
| 控制与配置 | 前进/转向、踱步、返回前进、渐弱、撤销与时长上限 |
| 可保存输出 | 反馈时间线、命令、脚印/声音参数和切换原因 |
| 展示证据 | 真实运动信号与反馈曲线、状态转换图、一条无响应到踱步的标注时间线 |

## 完成条件

正常响应、持续无响应、延迟响应、原地动作、缺测、无效来源和再冻结均有可复现案例。B2 能验证未知不当作失败、原地不当作前进、每次提示最终停止。当前模块基础不代表真实反馈与完整联调已完成。
