# B1：运动反馈与提示控制

## 当前状态与目标

A 组感知已在 `main` 交付。B1 从真实 IMU、`perception_runtime.csv` 和提示生效记录开始，实现运动反馈代理，并接入前进/转向提示、有效无响应观察、原地交替踱步、返回前进及退出。

现有 `cueing/guidance.py`、`cueing/march.py`、`cueing/targets.py`、`cueing/contracts.py` 和 `data/responses.py` 提供可运行的模拟控制基础；真实 IMU 反馈和对应适配仍待实现。最终人物、场景、PPT 和视频由工业设计负责。

`motion/baseline.py` 已有动态加速度 RMS 的通用活动状态基线，可作为运动特征参考；它尚未构成提示后响应估计器。其 `SensorWindow` 加速度单位是 m/s²，FoG-STAR 原始加速度是 g，接入时必须显式转换。模拟控制默认配置位于 `config/guidance.yaml`。

## 分步任务

| 任务 | 具体工作 | 保存产物 | 完成条件 |
|---|---|---|---|
| B1-01 真实运动代理 | 从左右踝运动能量、峰值或周期建立可解释判据；固定观察窗、预处理、阈值与质量门控 | 反馈估计器、配置、`feedback_runtime.csv` | 动作证据、有效无动作、未知分别可复现；保留记录键、来源和可用时间 |
| B1-02 来源保真的适配 | 为 IMU 代理建立模块内输入/适配器，分别处理模拟响应及代理反馈 | 适配器、字段说明、来源与缺测检查 | 代理不填写虚构落脚坐标，不把 `derived_proxy` 伪装成 `simulated` |
| B1-03 有效无响应观察 | 从提示生效时间起，仅在反馈有效且支持无动作时累计观察时长 | 计时状态、累计有效时长、暂停/重置原因 | 缺测、过期、低可靠性和观察不足不推进失败时钟；重复保持行不增加观察 |
| B1-04 控制闭环 | 接入前进/转向、踱步、交替动作完成后返回前进、渐弱和停止 | 控制配置、命令 CSV、每次切换原因 | 每条转换有输入证据；未知/过期输入及时撤销；所有提示最终关闭 |
| B1-05 过程与异常证据 | 保存真实信号/反馈曲线及一条无响应到踱步的过程，提交异常案例 | 简短说明、图表、案例输入输出 | B2 能用同一输入核对行为；代理/模拟/不可评价项标识清楚 |

上述产物是后续交付目标。当前 `validate_step_responses` 只接受 `source=simulated`；成功响应需要脚别和有限位置。B1 必须显式设计代理反馈接入，不能直接把目标字段当作已经实现的控制输入。

## 反馈判据与动作语义

- `step_evidence / no_step_evidence / unknown` 必须附质量、来源和解释。仅有 IMU 运动时标为 `feedback_source=derived_proxy`、`feedback_kind=movement_only`，不宣称测得向前位移。
- 没有足够有效观察时保持未知；方向拒识、冻结模型阴性或感知 `recovery` 都不等于没有迈步/已经恢复。
- 踱步交替计数需要可靠脚别与独立动作观测。脚别不可靠时，不靠左右脚印的预设交替虚构实际完成次数。
- 允许经可靠原地交替证据返回“尝试前进提示”；这不代表已完成向前恢复。退出、感知回落与实际运动反馈各自保留原因。
- 没有独立步真值或位置真值时，代理分类准确率/迈步成功率标为不可评价；可展示判据行为、质量覆盖和人工核查范围。

## 参数与异常验收

现有工程默认值包括 3 秒响应超时、3 秒备用阶段和 4 次交替动作。B1 需在配置中明确实际采用值，并验证节拍、观察窗口、交替要求和备用时长能同时满足；不要把这些默认值当作患者参数。

| 必需案例 | 预期核对重点 |
|---|---|
| 正常/延迟动作 | 提示后才观察，可靠响应不误计为持续失败 |
| 持续有效无动作 | 满足配置条件才进入踱步，切换有累计有效时长依据 |
| 原地交替/错误脚别 | 可靠交替才计数，原地动作不计作向前恢复 |
| 缺测/断档/低可靠性 | 反馈未知，失败时钟暂停或重置，撤销与降级原因明确 |
| 方向未知/来源过期 | 不强行设为直走，不无限保持提示 |
| 记录切换/再冻结/结束 | 状态不串用，重触发可解释，每次命令最终关闭 |
