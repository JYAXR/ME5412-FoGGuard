# A2：转向识别与感知融合

## 目标和边界

完成直走/左转/右转/不确定识别，单独研究转向前方向预测，并把方向结果与 A1 的冻结结果接成可用的感知时间线。A1 已交付冻结模型；A2 不重新承担冻结模型训练，也不负责最终 3D。

## 输入与代码基础

- A1 模型包与 [推理入口](../A1_A2_START_HERE.md)。接入参考选择 `bilateral_rf`。
- FoG-STAR 原始 IMU、活动标签和 `config/fog_selected.json` 的人员划分。活动 1 为直行、6 为右转、7 为左转；其他/混合窗口需保留拒识语义。
- `src/fogguard/turning/` 提供方向规则，`context/fogstar.py` 提供确认、迟滞、恢复、方向平滑与质量门控。
- `evaluation/readiness.py` 的 `preturn_candidates` 可检查正例输入可用性，完整训练还需负例与人员隔离。

## 实施顺序

1. 运行 A1 包的合成接口样例，核对字段、单位和可用时刻。
2. 固定方向输入通道及轴向，建立当前方向数据集；训练/验证按参与者隔离。先提供可解释基线和混淆矩阵，再确定最终方向模型。
3. 单独建立转向前任务。输入结束早于标注起点 0.5 或 1.0 秒，构造左右转正例及无即将转向/非转向过渡负例。相邻同一转向片段不得随机分散到不同集合。未来标注只用于目标。
4. 当前方向和提前方向分别输出，报告提前量、逐类召回、误报/分钟、拒识覆盖与漏检；无足够证据时保留当前方向方案。
5. 编写 A1 输出与方向输出的适配器，按记录和真实可用时刻对齐，来源有效期最多 0.5 秒。未知方向不能强行设成直走，过期结果不能无限沿用。
6. 接入现有事件聚合，导出无真值运行时间线，以及独立评价真值；交给 B1 和 B2。

## 必交付

| 交付 | 内容 |
|---|---|
| 方向模型和配置 | 输入、预处理、训练人员、阈值/拒识规则与推理入口 |
| 方向评价 | 各类 P/R/F1、macro-F1、混淆矩阵、逐人结果、覆盖率 |
| 转向前任务结果 | 正负例定义、提前量、成绩或明确不可用原因 |
| 感知适配器 | A1 与方向对齐、时效/断档处理、事件字段 |
| 展示材料 | 一张处理流程图、一张方向混淆矩阵、一条真实信号/方向/FoG 对齐时间线 |
