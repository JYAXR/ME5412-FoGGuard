# 五人分工与三周路线图

## 需求输出与实施边界

本轮工作以产品和需求输出为主：在现有 README、架构文档和本路线图中明确项目目标、使用场景、优先级、验收标准与责任归属。当前文档更新不修改代码、接口、测试或数据，也不表示以下待办已经完成。

需求以 [README](../README.md) 的项目范围和[架构文档](ARCHITECTURE.md)的 FR-01 至 FR-08 为依据。P0 必须完成；P1 在 P0 完成后探索；Future 不纳入本期验收。具体算法、参数与实现方案由开发负责人提出。

## 角色与交付物

| 角色 | 主要责任 | 可验收交付物 | 互审/备份 |
|---|---|---|---|
| 机器人 1——数据与 FoG | 数据、回放、FoG 检测需求落地 | 场景及标签说明、评分与判断输出、检测失败案例；对应 FR-01、FR-02 | 自动化 2 |
| 机器人 2——情境与集成 | 直走/左右转弯识别、模块连接 | 情境结果及不确定处理、端到端回放；区分当前识别与提前预测；对应 FR-03 及集成 | 自动化 1 |
| 自动化 1——提示与控制 | 情境策略、触发与退出、异常处理 | 策略表、决策原因、提示历史、不应期、恢复和降级行为；对应 FR-04 至 FR-06 | 机器人 2 |
| 自动化 2——评估与质量 | 验收口径、对照评估与可复现性 | 分场景检测/情境/提示指标、验收记录、错误分析；对应 FR-08，并验证 FR-01 至 FR-06 | 机器人 1 |
| 工业设计——体验与表达 | 演示需求、信息表达与使用流程 | 评分、情境、事件阶段、提示原因展示；可用性走查与展示材料；对应 FR-07 | 全组 |

项目协调人兼任需求维护：确认范围、记录需求变更、协调跨模块依赖，避免将未实现功能写为现有能力。每位成员仍需完成自身技术交付并审查另一角色的 PR。

## 已有基础与当前缺口

以下为 2026-10-18 的代码检查结果，不代替运行验收。

- **已有基础**：合成正常/直行 FoG/转向 FoG 场景、CSV 回放与 FoG 标签对齐、频域检测基线、阈值标定、窗口级指标、简单转向与提示规则、Streamlit 页面及基础测试。
- **部分实现**：转向方向识别、提示选择、不应期判断与集成展示。仍需完善情境可靠性、提示历史接入、恢复退出、异常降级和原因展示。
- **待开发或验证**：事件与提示时序指标、情境评估、统一策略对照、边界场景和端到端验收。
- **探索范围**：起步情境和听觉/视觉策略比较；使用人工指定或合成情境时明确标识。
- **未来方向**：步长估计、个性化干预、真实硬件及人体研究。

现有阈值标定记录保留为合成数据的工程证据，不改写为临床性能结论。

## 三周交付顺序

以下按阶段安排交付，不代表重新开始三周，也不把已有代码视为尚未开展。团队可按实际进度补齐缺口；未通过验收的项保持待办。

### 第 1 周阶段——对齐需求与接口职责

目标：共同确认“做什么、已有多少、如何验收”。

- 对齐项目目标、三个研究问题和 P0/P1/Future 范围。
- 核查现有流程，逐项标记已有、部分实现、待开发。
- 明确 FoG 评分、转向状态、事件阶段和提示命令的含义。
- 确定 P0 场景、预期行为和标签来源；需要接口调整时先提出方案。
- 用现有基础完成一次正常、直行 FoG、转向 FoG 回放验收。

阶段交付：需求与责任对应清楚；各负责人能说明输入、输出、依赖和验收方法；现有运行结果有记录。

### 第 2 周阶段——补齐 P0 行为与评估证据

目标：将需求转成可检查的模块行为。

- 数据与情境负责人补充右转、正常转弯、主动停步、恢复及异常输入场景。
- 控制负责人落实提示历史、不应期、恢复退出和异常降级；展示负责人同步展示原因。
- 评估负责人固定事件与提示计数、延迟和对照口径；只在记录的开发数据上调参。
- 对同一输入比较统一提示与情境自适应策略，分别报告给定情境测试和端到端结果。
- 进行一次五人演示流程走查，并记录至少三个代表性错误及其原因。

阶段交付：FR-01 至 FR-08 有验收记录；未满足项有明确负责人和后续安排。无标签或未实现的指标不得以零错误代替。

### 第 3 周阶段——冻结、复核与展示

目标：完成可靠的五分钟演示和有证据边界的报告。

- 周中前冻结 P0 范围、接口和最终候选配置；P1 不影响核心交付。
- 复核异常输入、重复触发、恢复退出及端到端场景。
- 在固定留出场景上完成评估，附数据版本、配置、命令和局限性。
- 展示内容串联“问题 → 需求 → 原型 → 结果 → 局限”；区分检测性能、策略符合度和未验证的临床效果。
- 完成两次全流程彩排、一次演示失败后的恢复彩排，准备备用视频和演示版本标签。

最终交付：可复现演示、需求验收记录、分场景指标与错误分析、明确局限性的展示材料。性能不足时如实解释，不能靠修改留出集或隐去失败场景达成表面验收。
