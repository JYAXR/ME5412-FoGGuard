## 复现

在代码目录按原 README 安装依赖及项目后执行：

```powershell
python -X utf8 scripts/run_complete_checks.py
```

未安装为包时，可先在 PowerShell 执行 `$env:PYTHONPATH="$PWD\src"`。
检查入口自动设置 UTF-8 与数学库线程数，不修改 Windows 系统设置。
输出到 `reports/complete_checks`，包括测试日志、原自动化 2 评估及完整演示。
目录已存在时同名文件会覆盖；保留实验请使用新的 `--output-dir`。

外部候选入口：

```powershell
python -X utf8 scripts/run_complete_demo.py --predictions docs/examples/robot2_predictions.csv
python -X utf8 scripts/run_complete_demo.py --config config/complete_demo.yaml
```

CSV 可以是原模型保存的候选概率，字段沿用机器人 2 的交接契约。
提供 `--responses` 时响应必须声明 `source=simulated`，并按场景明确配对。
没有独立真值时，只生成行为记录，检测指标明确标注不可用，不补造真值。

## 新增踏步的定义

- `MarchConfig.enable_march_fallback` 独立开关；关闭时调用原控制器路径。
- 只在响应源明确配置且可用、已确认冻结、核心输入有效时启用一次备用。
- 沿用原版备用时长，默认 3 秒；需要 4 次可靠、及时、正确脚别的交替原地响应。
- 原地前进位移绝对值最多 0.08 m，必须低于原向前完成阈值 0.15 m。
- 原地脚印围绕当前配置示意锚点，不随踏步累计向前移动。
- 达到阈值后返回向前目标。原地响应不计作向前恢复、稳定步数或间距调整依据。
- 错误脚别或不合适位移不计成功；无法完成/无响应撤销累计证据。
- 响应输入缺失退化固定提示；核心输入异常撤销双模态。持续事件仍受原时长上限约束。
- `guidance-march-v1` 是本独立集成版本的扩展格式，新增 `MARCH_FALLBACK` 和
  `march_alternating`；不替团队宣布共享在线契约已冻结。

## 对照与证据

固定策略、原倒计时、自适应踏步、仅关闭渐弱、仅关闭间距调整消费同一份输入和响应。
踏步与倒计时的对照只改变踏步开关，两个单因素消融也只改变各自的配置项。
响应预设不会因策略改变，因此不能将提示时长或状态差异解释为患者疗效。
`manifest.json` 保存配置、汇总和外部输入哈希；`data_hashes.json` 记录 CSV 哈希。

## 对原文件的影响

原工作目录和 v1/v2 交付不覆盖。本独立副本仅调整两个已有文件：

1. `cueing/replay.py` 新增可选控制器类型参数，默认仍用原控制器。
2. `pyproject.toml` 声明新展示模板为包数据，保证安装后仍可生成页面。

其他功能放在新模块。原算法、控制器、共享 `types.py/interfaces.py` 和原测试保留。
当前通过独立贡献分支和 PR 交付，版本附件见 [总入口](../AUTOMATION2_START_HERE.md)。不自动合并、不关闭 Issue。
