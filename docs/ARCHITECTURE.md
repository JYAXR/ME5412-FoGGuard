# 系统架构与验收

## 模块关系

数据层提供按记录隔离的 IMU 和质量信息。A1 输出冻结候选，A2 输出方向并形成感知事件。B1 根据感知、提示记录和运动反馈生成脚印/声音命令。B2 验证全链路，工业设计读取保存的结果呈现。

运行数据与评价真值分别保存。模型输出以 `available_at_s` 为实际可用时刻，不能回填到输入窗口起点。

## 当前代码和任务

| 层 | 现有代码入口 | 当前能力 | 剩余交付 |
|---|---|---|---|
| A1 | `selected_fog.py`、`modeling/a1_*.py` | 三种冻结模型，统一预测与同窗评价 | 接入支持 |
| A2 | `turning/learned.py`、`perception.py`、`context/fogstar.py` | 当前方向模型、拒识、按来源可用时刻融合、事件确认与恢复观察 | 独立方向验收、B1/B2 接收验收 |
| B1 | `cueing/guidance.py`、`cueing/march.py`、`data/responses.py` | 脚印声音控制与模拟响应驱动的踱步 | IMU 运动代理、反馈映射、有效观察计时及联合验证 |
| B2 | `evaluation/`、`recognition/`、工程比较脚本 | 窗口/事件/时间审计、生命周期审计、策略对照 | 四模块接线、统一指标与最终展示数据包 |
| 展示 | `presentation/`、`ui/` | 保存结果回放及曲线页面 | 工业设计完成最终可视化和 PPT |

`run_complete_demo.py` 使用构造候选与模拟响应。真实 A1+A2 感知使用 `validate_perception.py`，已有开发验证人员的无标签推理回放；真实反馈和四模块联合验收仍待 B1/B2 完成。运行方法见 [感知交接](a2/fusion/README.md)。

## 时间与数据规则

- A1 输入 120 点、60 Hz，步长 30 点；输出在完整窗口末端可用。
- 正式感知适配要求每个来源的结果最多保持 0.5 秒。超过时效设为未知；不同窗口长度按各自可用时刻对齐。
- 适配器对每个来源要求 `available_at_s <= now < window_end_s + 0.5`；计算延迟占用这段有效期，到期立即撤销。离线模型当前采用窗口末端可用的约定，不代表测量了实时计算延迟。
- 现有事件与控制模块的年龄门限为 1.0 秒、缺口门限为 0.75 秒。正式感知适配器使用更严格的来源有效期，事件计数只在新观测上推进；保持值和计时行不增加证据。
- 记录变化、时间倒序、缺测及断档必须重置或拒绝；缺失输入不补成正常状态。
- A1 原始加速度单位为 g；通用 `SensorWindow` 使用 m/s²。转换由数据适配层显式执行，禁止混用。

## 感知状态与控制状态

感知事件为 `normal / suspected / confirmed / recovery / safe_none`。现有事件基础使用两窗确认、三窗恢复观察和迟滞；A2 记录实际采用的配置。`recovery` 表示检测结果回落，未证实向前迈步。

控制目标为：

| 状态 | 条件与行为 |
|---|---|
| IDLE | 没有确认事件，保持无救援提示 |
| GUIDING | 事件确认且方向有效，显示前进或转向脚印与节拍 |
| RESPONSE_OBSERVATION | 有提示且观察有效，累计响应证据或有效无响应时长 |
| MARCH_FALLBACK | 有效无响应满足条件，显示左右交替原地目标 |
| RETURN_FORWARD | 达到原地交替动作条件，重新尝试前进目标 |
| RECOVERY / FADING | 根据感知及有效响应条件维持、渐弱并退出 |
| SAFE_NONE | 必要输入未知/过期、反馈不可用或达到上限，撤销对应提示 |

这是目标行为层次，具体状态名称可由 B1 映射至现有控制器。反馈缺失时不累计“未迈步”证据；原地交替动作不能计作向前恢复。当前控制器仅接收 `source=simulated` 的响应文件，IMU 代理接入由 B1 明确实现，不可伪装成模拟落脚坐标。

## 验收要求

| 编号 | 负责人 | 验收内容 |
|---|---|---|
| FR-01 | A1 | 三模型运行、特征/输入配置、FoG P/R/F1 与误报漏检证据 |
| FR-02 | A2 | 方向各类指标、拒识覆盖率、转向前任务独立目标和评价 |
| FR-03 | A2 | A1 与方向按记录和可用时刻融合，确认/恢复/未知行为正确 |
| FR-04 | B1 | 反馈有动作/无动作/未知，含可靠性、来源与有效时间 |
| FR-05 | B1 | 无响应后进入原地踱步，交替完成后返回前进，每次切换有原因 |
| FR-06 | B1 | 提示有明确启停，时长受限，过期和不可用输入及时撤销 |
| FR-07 | 工业设计 | 保存结果驱动最终展示，脚印、声音、来源与状态可读 |
| FR-08 | B2 | 独立真值对照、相同输入策略比较、失败案例和复现结果 |
| EX-01 | B1/B2 | 有效运动响应与向前位移证据分开，unknown 不累计失败时钟 |
| EX-02 | B1/B2 | 当前目标稳定，间距在配置范围内，渐弱与重启有对照 |
| EX-03 | B2 | 原地交替步数、节奏和备用时长一致，包含慢响应及超时场景 |
| EX-04 | 全组 | 真实、代理、构造、模拟来源明确，无标签泄漏和疗效混报 |

接口字段见 [接口约定](INTERFACE_CONTRACT.md)，具体任务与交付见 [分工](ROLES_AND_ROADMAP.md)。`types.py`、`interfaces.py` 的共享协议保持独立，模块适配提案经接收方评审后实现。
