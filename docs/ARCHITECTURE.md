# 系统架构、功能需求与验收

本文定义模块职责、产品需求与验收口径。标为“目标需求”的内容交给开发成员实现，不代表当前代码已经支持。机器人 1 已增加公开真实数据适配和评估，但没有修改共享数据类或模块协议。

## 先看懂整体流程

系统先读取步态数据，判断是否冻结以及正在直走还是转弯，再决定脚印与声音如何提示，最后展示原因并记录结果。若要根据迈步结果继续调整，还需明确提供模拟落脚与响应输入。

完整仿真按两阶段实现：P0 打通基础流程，P1 接入踏步备用、下一步间距调整、稳定后渐弱与冻结后恢复。两阶段分别验收；P1 属于完整目标，不能把仅完成 P0 写成全部实现。提前提示和患者响应模型仍为可选探索。

最终展示形式待团队确定。二维/三维人物、手动操控、随机场景和声音播放方式尚未选定，不作为本轮新增验收要求。下文约束的是系统行为与证据来源，不限定具体界面形式。

五人分工保持不变：数据负责人同时提供合成工程场景、公开真实数据基准和模拟响应，控制负责人决定提示参数，体验负责人设计呈现，集成负责人协调接入，评估负责人提前组织检查。具体衔接见[分工文档](ROLES_AND_ROADMAP.md)。下文保留供开发和验收查阅的技术细节。

## 现有流程与差距

`WindowReplay` 每 0.5 秒输出一个长度为 2 秒的 `SensorWindow`。FoG 检测和转向模块分别处理同一窗口，其结果通过 `ControllerContext` 交给控制器，返回 `CueCommand`。UI 展示结果，FoG 评估调用同一检测模块。

当前基础包括频带能量评分、角速度方向规则，以及按转向情况选择触觉或声音的提示规则。主要差距：

- 控制器按 FoG 评分判断，没有完整的事件阶段管理；检测默认阈值与控制器默认门限不同，UI 又以同一滑块覆盖两者，需要统一说明语义。
- 控制器有不应期判断，但 UI 未传入上次提示间隔，端到端重复提示限制尚未落实。
- 现有控制器未检查转向置信度或输入时效；当前数据契约也未完整表达这些信息。
- 恢复观察、起步情境、脚印投影演示和视觉策略尚未实现；UI 尚未展示提示原因。现有 CueCommand 只表达单一提示类型，不能原生表达双模态同步、左右目标位置或渐弱轨迹，需要开发负责人提出兼容扩展方案。
- 当前 `probability` 是频带能量占比评分，转向 `confidence` 是启发式数值，均不能直接解释为经过校准的正确概率。

## 目标信息流与职责

目标需求：输入质量 → FoG 相关事件判断与步行情境识别 → 提示决策 → 展示与记录 → 评估。具体算法和接口方案由对应负责人提出。

| 模块 | 输入与职责 | 需要交付的信息 |
|---|---|---|
| 数据 | 同步的 IMU 数据、时间信息；评估时另有标签 | 可用窗口、数据来源与质量问题 |
| FoG 检测 | 传感器信号；识别 FoG 相关特征 | 评分、判断、判据和结果对应的时间 |
| 情境识别 | 传感器信号；识别直走与左右转弯 | 情境、可靠性及不确定原因 |
| 提示控制 | 检测结果、情境、时间和提示历史 | 是否提示、提示策略、持续时间与可读原因 |
| 展示 | 模块输出与记录 | 评分、情境、事件阶段、提示及原因时间线 |
| 评估 | 模块输出与独立标签/预设行为 | 指标、失败案例、配置及复现方法 |

真实标签用于评估，不得作为自动识别或提示决策的输入。为独立验证策略而注入已知情境时，必须标为“给定情境的策略测试”，并与端到端识别结果分别报告。

## 情境与事件阶段

步行情境和 FoG 事件阶段应分别表达，因为“转弯”和“发生 FoG”可以同时成立。下列为需求概念，不要求开发直接采用同名枚举。

- 本期情境：直走、左转、右转、不确定；主动停步用于检验误判。冻结后的重新启动纳入 P1；起步前提前提示为可选探索，缺少可靠依据时只能做明确标注的策略仿真。
- 事件阶段：未检测到、疑似、持续检测到、恢复观察。进入和退出条件由开发提出、在开发场景上确定，并固定后再评估。
- “未检测到”不等于确定没有 FoG；“恢复观察”表示检测输出恢复，不能解释为已经证实患者恢复。
- 低 FoG 评分与低判断可靠性是不同概念；低角速度也不应直接等同于情境不可靠。

## 提示策略需求与证据边界

目标产品以投影脚印与声音节奏为主要输出，直行和转弯均可使用。本期在屏幕中表示脚印和声音提示状态，不控制真实设备。现有声音/触觉映射保留为可复现基线，不代表最终产品选型或最优干预。演示参数不是临床处方。

| 场景 | 目标行为 | 范围与输入条件 |
|---|---|---|
| 正常行走、主动停步或正常转弯 | 不触发冻结救援；持续引导须是显式选择的模式 | P0；不能因停止或转弯本身认定 FoG |
| 直走时持续检测到 FoG | 显示预设可完成步幅的前方脚印及声音提示状态，记录原因 | P0；个人步幅为演示配置，不能冒充传感器测量 |
| 转弯时持续检测到 FoG | 显示相应方向的脚印路径和声音提示状态 | P0；脚印方向和布局有差异，无须强制切换提示模态；没有位置定位时路径为示意 |
| 检测输出持续恢复 | 经观察退出救援提示，并记录切换过程 | P0；只证明检测状态变化，不证明患者平稳或提示有效 |
| 输入缺失、过期或相关判断不可靠 | 输出 NONE 与原因，停止使用过期定位或状态 | P0；与普通未检测到 FoG 分别记录 |
| 目标提示后仍无法启动 | 可切换原地左右交替踏步提示，出现有效响应后再引导向前 | P1；需要模拟或经过验证的响应输入；踏步为可选策略，次序可配置 |
| 已恢复连续步伐 | 根据最近几步完成情况调整下一步目标，保持个人范围内 | P1；需要落脚时刻、左右脚、位置/步长和可靠性；本期只能采用显式模拟输入 |
| 连续稳定表现 | 探索逐渐减弱视觉清晰度和声音音量，重新出现冻结时恢复已配置提示 | P1；平稳判据需要额外数据，保留持续提示作为对照；音量变化不等于节奏变化 |
| 起步前或转弯前准备 | 探索提前提示，不设为每次必经动作 | 可选探索；不能把当前转向识别当作提前预测 |

### 脚印与恢复交互约束

1. 冻结后给出的第一步应为个人可完成的目标，不要求最大步幅。无法启动不一定因为目标太远，须区分冻结、主动停止、未理解提示及定位不可靠。
2. 原地踏步指左右交替抬脚的候选恢复动作，不等同于已恢复向前行走，也不保证能解除冻结。不能仅因没有前移而把主动踏步判为失败。
3. 当前正在迈向的脚印保持稳定；确认落脚后才更新下一步。不能在摆腿过程中移动目标，让患者追逐脚印。
4. 目标间距参考个人预设范围与最近连续成功步伐；单次误差不立即触发调整，不随碎步无限缩短，也不要求每一步都增大。转弯同时考虑朝向、左右间距及路径。
5. 缺失落脚/响应数据时关闭相应自适应功能，展示信息不足；低 FoG 评分不能替代稳定性、步长或足部位置估计。
6. 分别配置视觉清晰度、声音音量、节拍与目标间距。冻结时恢复提示不自动加快节拍或增大步幅。连续事件内的提示维持/恢复与重复发出新提示应分别定义，避免不应期让整段救援失效。
7. 药物 ON/OFF 指药效状态，与提示开启/关闭无关。现有数据没有药物状态标签；本期不据此自动切换策略，不用低 FoG 评分推断 ON。

### 已有依据与未验证假设

| 来源 | 可以支持的设计判断 | 不能推导的结论 |
|---|---|---|
| [Cosentino 等，2023，系统综述](https://doi.org/10.1016/j.neubiorev.2023.105189) | 起步、行走、转弯及具体指标应分别评价 | 本项目映射最优，或步态参数改善必然减少 FoG |
| [ANPT，2022，冻结应对资料](https://www.neuropt.org/docs/default-source/default-document-library/freezing-strategies-in-parkinson-disease---patient-final.pdf) | 视觉目标、声音节奏、踏步等可作为个体化候选策略 | 所有人都需要踏步，或“先迈步、失败后踏步”已由试验证明 |
| [Hoogendoorn 等，2024](https://pmc.ncbi.nlm.nih.gov/articles/PMC11037397/) | 21 名 PD 参与者可随不同视觉目标调整步长，支持可配置间距 | 根据每步误差自动调整能减少冻结 |
| [Sun 等，2017](https://pubmed.ncbi.nlm.nih.gov/28837917/) | 健康青年/老年人的目标突变研究提示调整时机影响准确性与稳定性，为保持当前目标稳定提供间接依据 | 该规则已在 PD 患者中验证有效或可预防跌倒 |
| [Zoetewei 等，2024，DeFOG 随机试验](https://pubmed.ncbi.nlm.nih.gov/38486430/) | 检测后按需声音提示有临床研究依据，使用时有即时获益 | 渐弱亮度/音量优于持续提示，或视觉加声音必然更好 |

完整的“迈步目标—踏步备用—恢复前进”、自适应间距与渐弱组合尚待验证。各因素应单独比较，不能一次同时改变全部参数后归因于其中某一项。

## 数据与仿真的可验证范围

合成 CSV（见 [DATA_SCHEMA.md](DATA_SCHEMA.md)）包含 IMU 时间序列与 FoG/转向标签，但缺少真实左右脚落地、步长、足部位置、稳定性、提示接受情况及药物状态。生成器提供 50 Hz、30 秒的确定性信号，并已覆盖左右转、主动停步和恢复等工程场景。Daphnet 提供 64 Hz 真实患者加速度与 FoG 标签，但不提供陀螺仪、转向真值、足部位置或提示响应。

- **数据驱动回放（P0）**：信号输入检测与转向模块，再由输出驱动提示。标签只进入评估，不能泄漏给决策。检验检测准确性、时序、方向、异常降级及可解释性。
- **给定输入的策略仿真（P1）**：另行明确模拟的落脚与响应事件及来源，检查策略转换、目标调整边界和渐弱/恢复。屏幕不能把这些输入显示为患者实测或自动识别结果。
- **响应模型探索（P1，可选）**：如果提示会改变后续模拟步态，必须记录模型假设，比较无响应、延迟响应及恶化情况，并做参数敏感性分析。不得把预设“提示后恢复”的脚本作为疗效证据。
- **公开真实数据验证（P0）**：使用 Daphnet 做按参与者留一验证，固定许可、传感器位置、轴向、单位、采样率、标签映射和数据哈希；结果见 [Daphnet 验证记录](DAPHNET_VALIDATION.md)。存在 FoG 标签不代表存在转向或步长真值，无对应标签的指标报告为不可评估。
- **新的真实数据采集（Future）**：新的参与者招募、穿戴采集和提示响应试验须另行获得教师同意及适用的伦理审批，不纳入本期两周计划。

P0 不依赖闭环患者响应模型即可完成；其性质是离线回放和控制行为验证，不是临床闭环验证。

## P0 功能需求与验收

| 编号 | 需求 | 验收方式 |
|---|---|---|
| FR-01 | 可复现地回放数据并说明其来源、采样设置和标签假设 | 同一数据与配置得到相同输出；已有正常、直行 FoG、转向 FoG 场景可运行 |
| FR-02 | FoG 输出可解释且不夸大评分语义 | 记录评分、判据、门限与判断；页面及报告称为评分，说明未校准为临床概率 |
| FR-03 | 区分直走、左右转弯与不确定 | 左右转及正常转弯用例分别检查；不宣称尚未验证的提前预测能力 |
| FR-04 | 按情境和阶段给出脚印与声音提示状态 | 相同检测输入下，直行和左右转弯的方向/布局符合声明；区分配置路径与实测位置；输出包含原因 |
| FR-05 | 限制重复提示，并在恢复后退出 | 持续事件、不应期边界、反复跨阈值和恢复场景均有预期时间线；回放实际使用提示历史 |
| FR-06 | 异常或不可靠输入进入无提示状态 | 缺失、非有限数值、过期及情境不确定用例输出 NONE 和具体原因 |
| FR-07 | 页面展示脚印、声音状态及决策依据 | 可查看评分、情境、阶段、提示、原因与时间；区分检测输出、配置参数和模拟输入，脚印展示不是实物投影验证 |
| FR-08 | 对检测、情境和提示分别评估 | 按下节口径提交分场景结果、失败案例及复现命令，未实现或无标签的项目明确标记 |

功能验收按预设行为判定通过与否。性能目标由团队在开发阶段根据数据条件确定并记录，不预先承诺 F1、延迟或临床效果；不得看过留出结果后再修改目标并称为独立验收。

## P1 完整交互验收（在 P0 基础上接入）

| 编号 | 需求 | 验收方式 |
|---|---|---|
| EX-01 | 可选踏步备用及返回前进提示 | 在给定响应/无响应场景检查状态转换，区分原地踏步和向前步伐，不强制所有配置使用踏步 |
| EX-02 | 根据落脚反馈更新下一目标 | 检查摆腿期间目标不变、落脚后更新、调整范围和缺失输入；用配置边界检查，不声称已证明临床安全 |
| EX-03 | 稳定后渐弱、冻结后恢复 | 固定平稳判据与淡出/恢复参数，记录提示覆盖时长和切换次数，包含持续提示对照 |
| EX-04 | 仿真证据来源透明 | 每个输入标明来源；模拟响应指标与检测指标分表；缺失真值不报告零错误 |

## 评估与对照要求

- **FoG 窗口指标**：precision、recall、F1 和混淆计数；保留现有默认“窗口内至少 50% 采样点为 FoG”的标签口径。
- **FoG 事件指标**：另行声明事件合并、匹配和漏检规则。检测延迟从标注事件开始到首次检测输出的可用时刻计算；不能用窗口起点代替输出时刻。
- **情境指标**：按直走、左转、右转分别报告结果及混淆情况；说明标签聚合方式、不确定输出占比和缺失标签的处理。
- **提示指标**：按一次实际触发的命令计数，不能把同一提示覆盖的多个窗口算作多次触发。误提示/分钟需明确哪些已标注区间不应提示及有效评估时长；缺失标签不能当作正常区间。
- **延迟口径**：分别报告事件开始到首次提示、检测输出到首次提示的延迟。漏检或没有提示的事件单列，不能仅报告成功事件的平均值。
- **策略对照**：固定策略与情境/阶段自适应策略使用相同输入和检测输出。P0 比较方向/布局符合度、次数和延迟；P1 分别比较直接目标/踏步备用、固定/自适应间距、持续/渐弱提示，每次只改变声明的因素。对照固定共同约束；无差异也如实报告。
- **证据限制**：策略符合度仅说明实现符合事先定义的规则。开放式离线回放不会因提示改变后续步态，不能用于证明 FoG 被缓解或预防。
- **实验记录**：保存数据版本、开发/留出划分、配置、运行方法和错误案例。现有合成数据来自同一生成器，其留出结果不代表跨患者泛化。

## 模块边界与接口规则

- 共享数据契约定义在 `types.py` 和 `interfaces.py`；本文不新增或修改实际接口。
- 评分、概率和置信度的数值范围及语义须明确；仅处于 `[0, 1]` 不代表已校准为概率。
- 时间戳和持续时间使用秒，加速度使用 m/s²，角速度使用 deg/s，轴顺序固定为 x、y、z。
- 相同输入和配置须得到确定、可复现的结果；UI 展示模块输出，不另写一套检测或控制规则。
- 因需求需要改变共享接口时，须先建立接口 Issue、与相关负责人确认并更新本文，再由开发实现。

## 两周内明确不做

实时硬件数据流、深度学习部署、移动端应用、个性化临床调参、闭环物理执行和人体参与者验证不属于本期范围。投影脚印和声音是目标产品输出，本期用屏幕演示；投影定位、亮度、光学安全及硬件同步需后续选型与验证。课程说明允许概念、设计与仿真，未要求实体原型；不能以此省略现有方案对比、明确创新点或验证局限。
