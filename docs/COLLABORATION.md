# 协作与交接

## 分支与职责

分工以 [角色与交付顺序](ROLES_AND_ROADMAP.md) 为准，完成状态以 [项目状态](PROJECT_STATUS.json) 为准。整合基线为 `main`，当前 A1+A2 感知交接贡献分支为 `feat/a2-perception-fusion`。功能开发使用个人贡献分支，合并前由接收模块负责人审查。

每项任务应有明确负责人、输入输出、配置和验收结果。A1 已完成冻结算法交付；A2、B1、B2 的后续开发分别按任务书进行，工业设计消费保存结果。

## 开始工作

先读 README、项目说明、架构、接口和本人的任务书，再检查 Git 状态与代码。保留队友未提交工作，不覆盖目录，不重置分支或强推。

```bash
git status --short --branch
git remote -v
git fetch origin
```

从已确认的交接分支创建自己的 `feat/<主题>` 分支。不要把文档中的目标接口当作已经存在的实现。

## 接口变更

`types.py` 与 `interfaces.py` 的修改需要说明问题、具体字段、单位、时间、缺失行为和兼容方案，由发送方与接收方互审。模块内适配器先在独立接口中验证，不通过伪造来源或零值绕过质量检查。

## 验证和提交

```bash
python -X utf8 scripts/run_automation2_delivery_checks.py
git diff --check
git diff --stat
```

检查只包含本任务修改，再显式暂存源代码与文档。原始数据、模型权重、临床表和生成目录不提交 Git。新结果使用新目录，保存配置、输入和代码哈希；已有日期证据与附件保持完整。

## 完成定义

接收方能独立运行入口并理解字段；输出来源明确；必需验收有结果或明确未通过项；代码与说明已推送到贡献分支，合并经过互审。模块交付、系统联调、正式验收分别记录，不能用某一个完成状态替代整个项目完成。
