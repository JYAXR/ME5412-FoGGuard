# 协作与交接

## 当前基线与分工

默认基线为 `main`，A1/A2 感知及统一展示已合并交付。A 组负责维护和具体交接支持；B1 实现反馈与提示闭环，B2 承担接入/联合验证和展示包，工业设计制作 PPT 与最终演示。职责和依赖见 [规划](ROLES_AND_ROADMAP.md)，当前状态见 [清单](PROJECT_STATUS.json)。

功能开发或文档更新从最新 `main` 建个人贡献分支，评审后合并。不要继续把已完成的感知开发或独立测试列成 A 组训练待办。

## 开始工作

先读 README、项目说明、架构、接口和本人的任务书，再检查 Git 状态。保留队友未提交工作，不覆盖目录，不重置分支或强推。

```bash
git status --short --branch
git remote -v
git fetch origin
```

确认本地改动后，从已获取的 `origin/main` 新建 `feat/<主题>`。每项任务写明负责人、输入、配置、产物和完成条件；文档中的 B1/B2 目标字段、组合入口和最终导出器仍需实现，不视为现有能力。

## 模块接收

- A 组提供模型/运行说明、感知来源与时间语义；模型权重通过仓库外的交接包传递。
- B1/B2 核对同一记录身份、传感器单位、实际可用时刻、缺测与未知行为。接收复核属于下游任务，A 组提供按需支持。
- B1 代理反馈保留真实来源，不伪造位移；B2 固定同输入策略对照，并为工业设计提供可读命令与来源清单。
- 工业设计使用 [统一图表](a_group_showcase/index.html)，最终回放消费保存的输出，不重复执行算法或策略决策。

## 接口与结果变更

`types.py` 和 `interfaces.py` 的修改需说明问题、具体字段、单位、时间、缺失行为和兼容方案，由发送方与接收方互审。模块内适配器先独立验证，不通过零值或伪造来源绕过质量检查。

固定 TEST 已消费，现有模型/阈值与成绩保留。维护修复与新算法迭代分别记录；新训练任务需使用独立开发与评价方案，不能在同一已公开 TEST 上调参后宣称新的盲测。

## 验证与提交

```bash
python -X utf8 scripts/run_automation2_delivery_checks.py
git diff --check
git diff --stat
```

完整检查涵盖现有代码及工程场景，不能替代 B1 的真实反馈评价或 B2 的联合验收。省略原始数据/OOF 参数时，通用原始数据审计为 NOT_RUN。

检查仅包含本任务修改，显式暂存源代码与当前文档。原始数据、权重、临床表及生成运行目录不提交 Git。新的证据使用新目录及输入/配置/代码哈希；已发布的 A 组日期证据、独立测试和展示包保持完整。

## 交付完成定义

接收方能理解并运行入口，输出来源明确，必需检查有结果或明确未通过项，代码和说明已推送且经过评审。模块交付、联合验证、最终展示分别记录；已知性能限制保留在报告中，不转写成无期限待办。
